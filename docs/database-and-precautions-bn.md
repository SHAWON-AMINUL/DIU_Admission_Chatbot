# ডাটাবেজ কানেকশন, সতর্কতা ও Do's/Don'ts (বাংলা)

দৈনন্দিন সেটআপ/রান করার ধাপের জন্য [user-guide-bn.md](user-guide-bn.md) দেখুন। এই
ডকুমেন্টটা এর পরের স্তর — কীভাবে ডাটাবেজে সরাসরি ঢুকবেন, কোন কাজ বিপজ্জনক, এবং
কোন অংশ বন্ধ হলে কী ভাঙে।

---

## ১. ডাটাবেজে কানেক্ট করবেন কীভাবে

### সংযোগের তথ্য (এই মেশিনের local dev ডাটাবেজ)

| তথ্য | মান |
|---|---|
| Host | `localhost` |
| Port | `5433` (⚠️ 5432 না) |
| Database | `diu_admission` |
| Role/User | `diu` |
| Password | `diu` |
| পূর্ণ connection URL | `postgresql://diu:diu@localhost:5433/diu_admission` |

এই মানগুলো [`.env.example`](../.env.example) আর [`app/config/settings.py`](../app/config/settings.py)-এ ডিফল্ট হিসেবে লেখা আছে। `.env` ফাইলে `DATABASE_URL` না দিলে অ্যাপ এই ডিফল্টই ব্যবহার করে।

### পদ্ধতি ১ — `psql` টার্মিনাল থেকে (সবচেয়ে বেশি ব্যবহার করবেন)

```bash
PGPASSWORD=diu /opt/homebrew/opt/postgresql@18/bin/psql \
  -h localhost -p 5433 -U diu -d diu_admission
```

কানেক্ট হলে prompt দেখাবে `diu_admission=#`। ভেতরে ঢুকে যা করতে পারবেন:

```sql
\dt                          -- সব টেবিলের তালিকা
\d posts                     -- posts টেবিলের কলাম/টাইপ
SELECT * FROM posts LIMIT 5; -- ডেটা দেখা
\q                            -- বের হওয়া
```

একটাই কমান্ড চালিয়ে সাথে সাথে বের হয়ে আসতে চাইলে `-c` ব্যবহার করুন (আগের গাইডে যেমন করেছি):

```bash
PGPASSWORD=diu /opt/homebrew/opt/postgresql@18/bin/psql -h localhost -p 5433 -U diu -d diu_admission -c "SELECT count(*) FROM posts;"
```

### পদ্ধতি ২ — GUI টুল দিয়ে (TablePlus / DBeaver / pgAdmin / Postico)

উপরের টেবিলের তথ্য (host/port/db/user/password) সরাসরি বসিয়ে "New Connection" বানান। SSL/SSH কিছু লাগবে না — এটা লোকাল মেশিনেই চলছে।

### পদ্ধতি ৩ — অ্যাপ থেকে (কোড লেভেলে)

অ্যাপ নিজে থেকেই [`app/database/connection.py`](../app/database/connection.py)-এর মাধ্যমে কানেক্ট করে (`psycopg3` + connection pool, min 1 – max 8 কানেকশন)। এখানে কিছু ম্যানুয়াল করার দরকার নেই — শুধু Postgres চালু থাকলেই অ্যাপ নিজে কানেক্ট করে নেবে।

## ২. সতর্কতা (Precautions)

1. **`DATABASE_URL` / `.env` কখনো git-এ কমিট করবেন না।** পাসওয়ার্ড এখানে সরল হলেও ("diu"), অভ্যাসটা ঠিক রাখুন — `.env` সবসময় `.gitignore`-এ থাকা উচিত।
2. **`TRUNCATE` / `DROP` / `DELETE` চালানোর আগে দুইবার ভাবুন — এগুলো আনডু করা যায় না।** কোন ডাটাবেজে কানেক্ট আছেন (`-d diu_admission`) সবসময় কমান্ডে চোখে দেখে নিশ্চিত হন প্রোডাকশন ডাটাবেজে ভুল করে চালাচ্ছেন না।
3. **`pg_terminate_backend` দিয়ে কানেকশন বন্ধ করার সময় সবসময় `datname='diu_admission'` ফিল্টার রাখুন** — ফিল্টার ছাড়া এলোমেলোভাবে অন্য ডাটাবেজের সচল কানেকশনও বন্ধ হয়ে যেতে পারে।
4. **schema বদলাতে হলে সরাসরি `ALTER TABLE` চালিয়ে দেবেন না** — [`migrations/001_schema.sql`](../migrations/001_schema.sql) ফাইলটাই সত্যের একমাত্র উৎস (source of truth)। ওখানে পরিবর্তন লিখে তারপর প্রয়োগ করুন, নাহলে ফাইল আর আসল ডাটাবেজ আলাদা হয়ে যাবে আর পরে কেউ বুঝবে না কী আসলে চলছে।
5. **একই পোস্টে একসাথে একাধিক ট্যাব/ক্লিক থেকে approve/verify/publish চালাবেন না** — এতে row-lock একে অপরকে আটকে দেয় (deadlock)। একবারে একটা অ্যাকশন, একটা ট্যাব।
6. **uvicorn/embedding service-এর টার্মিনাল বন্ধ করার আগে ভাবুন** — Ctrl+C দিলে সেই মুহূর্তে চলতে থাকা কোনো request/ingest মাঝপথে কাটা যেতে পারে (post আটকে যেতে পারে `AI training in progress` অবস্থায়)।
7. **`--reload` চালু অবস্থায় কোড ফাইল সেভ করলে সার্ভার নিজে থেকেই রিস্টার্ট হয়** — সেই মুহূর্তে কোনো ইনজেস্ট চলতে থাকলে সেটাও মাঝপথে কাটা পড়তে পারে। বড় ইনজেস্ট চালানোর সময় কোড এডিট করা এড়িয়ে চলুন।
8. **সিড ডেটা (`scripts/seed.py`) বাস্তব তথ্য না** — এটা টেস্টের জন্য বানানো কাল্পনিক ডেটা, `[SAMPLE DATA]` হিসেবে মার্ক করা। আসল DIU তথ্য না ঢোকানো পর্যন্ত এই ডেটাকে সত্যি ধরে কোনো সিদ্ধান্ত নেবেন না।
9. **পোর্ট 5433 বদলাবেন না ছাড়া বিশেষ কারণ ছাড়া** — এটা ইচ্ছাকৃতভাবে 5432 এড়িয়ে বাছা হয়েছে যাতে মেশিনের অন্য Postgres ইন্সটলেশনের সাথে সংঘর্ষ না হয়।

## ৩. Do's ✅ / Don'ts ❌

| ✅ করবেন | ❌ করবেন না |
|---|---|
| সার্ভার চালুর আগে `pg_isready` দিয়ে Postgres রেডি কিনা চেক করা | Postgres চালু হওয়ার আগেই `uvicorn app.main` চালানো |
| Verify/Approve-এর পর টোস্ট মেসেজ আসা পর্যন্ত অপেক্ষা করা | একই বাটনে বারবার বা একাধিক ট্যাব থেকে ক্লিক করা |
| destructive SQL (TRUNCATE/DROP) চালানোর আগে কোন DB-তে আছেন তা যাচাই করা | ভাবনাচিন্তা ছাড়া কপি-পেস্ট করে SQL কমান্ড রান করা |
| schema পরিবর্তন `migrations/001_schema.sql`-এ লেখা | সরাসরি psql দিয়ে টেবিল/কলাম বদলে ফেলা (ফাইলে না লিখে) |
| তিনটা সার্ভিসই (Postgres, embedding, main API) আলাদা টার্মিনালে চালু রাখা | একই টার্মিনালে একটা বন্ধ করে আরেকটা চালানোর চেষ্টা করা |
| `/api/health` চেক করে কোনটা বন্ধ তা আগে বোঝা | সরাসরি অনুমান করে এলোমেলো ফিক্স চেষ্টা করা |
| `.env` লোকাল রাখা, gitignore-এ রাখা | `.env`/পাসওয়ার্ড কমিট বা শেয়ার করা |
| আটকে থাকা কানেকশন `datname` ফিল্টার দিয়ে টার্গেট করে বন্ধ করা | ফিল্টার ছাড়া সব ব্যাকগ্রাউন্ড প্রসেস/কানেকশন উড়িয়ে দেওয়া |

## ৪. কোনটা বন্ধ হলে কী ঘটে (Dependency / Failure Map)

> সংক্ষেপে: **ফ্রন্টএন্ডের পেজ লোড হওয়া** নির্ভর করে শুধু **মূল API (`uvicorn app.main`, পোর্ট 8000)** চালু থাকার উপর। কিন্তু পেজের **ভেতরের কাজ** (পোস্ট দেখা, সার্চ, চ্যাট, ইনজেস্ট) নির্ভর করে Postgres আর Embedding service-এর উপরও।

| যেটা বন্ধ/সমস্যাগ্রস্ত | সার্ভার (পোর্ট 8000) নিজে বন্ধ হয়ে যাবে? | ফ্রন্টএন্ড পেজ (`/`, `/chat`) ব্রাউজারে খুলবে? | কী আসলে ভাঙবে |
|---|---|---|---|
| **PostgreSQL (5433)** | ❌ না, uvicorn চলতেই থাকে | ✅ হ্যাঁ, পেজ খুলবে | পোস্ট লিস্ট, create/approve/verify/publish, চ্যাট/সার্চ — সবকিছুতে 500 error। ড্যাশবোর্ডের হেলথ স্ট্যাটাসে "database: not ok" দেখাবে |
| **Embedding service (8001)** | ❌ না | ✅ হ্যাঁ | `/api/search`, `/api/chat` ব্যর্থ হবে (500)। নতুন verify করা পোস্ট ইনজেস্ট **ব্যর্থ** হয়ে `AI training failed` হবে। কিন্তু posts list দেখা/create/approve/publish ঠিকই কাজ করবে (এগুলোর embedding লাগে না) |
| **Ollama (generation model)** | ❌ না | ✅ হ্যাঁ | শুধু `/api/chat` (পূর্ণ উত্তর তৈরি) ব্যর্থ হবে। `/api/search` (শুধু রিট্রিভাল, উত্তর জেনারেট করে না) ঠিকই কাজ করবে |
| **মূল API (`uvicorn app.main`, 8000) নিজে** | — (এটাই "সার্ভার") | ❌ **না**, ব্রাউজারে "connection refused"/"এই সাইটে পৌঁছানো যাচ্ছে না" | পুরো ফ্রন্টএন্ড অদৃশ্য — ড্যাশবোর্ড, চ্যাট, সব API — কিচ্ছু কাজ করবে না |
| **`.env`/`DATABASE_URL` ভুল লেখা** | ❌ না, চালু হয়ে যাবে | ✅ হ্যাঁ | পেজ খুলবে কিন্তু প্রতিটা DB-নির্ভর কল ব্যর্থ হবে — উপরের Postgres-বন্ধ কেসের মতোই আচরণ করবে |
| **`users` টেবিল খালি** | ❌ না | ✅ হ্যাঁ | নতুন পোস্ট তৈরি (`POST /api/posts`) ব্যর্থ হবে ("no users exist") — বাকি সব ঠিক থাকবে |
| **একাধিক ট্যাব থেকে একই পোস্টে verify/approve** | ❌ না (তবে ওই request-গুলো আটকে থাকবে) | ✅ হ্যাঁ | শুধু ওই নির্দিষ্ট পোস্টের row লকড থাকবে — অন্য পোস্ট/অন্য এন্ডপয়েন্ট প্রভাবিত হয় না, তবে অনেকক্ষণ চলতে দিলে connection pool (max 8) ভরে গিয়ে পুরো অ্যাপ ধীর/অকার্যকর হয়ে যেতে পারে |
| **`--reload` চালু অবস্থায় কোনো `.py` ফাইল সেভ করা** | সাময়িকভাবে হ্যাঁ (কয়েক সেকেন্ডের জন্য রিস্টার্ট হয়) | সাময়িকভাবে না (রিস্টার্টের কয়েক সেকেন্ড) | চলমান কোনো request/ব্যাকগ্রাউন্ড ইনজেস্ট মাঝপথে বন্ধ হতে পারে |
| **টার্মিনালে Ctrl+C দিয়ে uvicorn বন্ধ করা** | ✅ হ্যাঁ, সরাসরি বন্ধ | ❌ না | সেটা যে সার্ভিস ছিল (main API বা embedding service) সেটার সব ফাংশনালিটি বন্ধ — উপরের নিজ নিজ সারি দেখুন |

### দ্রুত ডায়াগনসিস

কিছু ভাঙলে সবার আগে এটা চালান:

```bash
curl -s http://127.0.0.1:8000/api/health | python3 -m json.tool
```

এটা `database.ok` আর `embedding_service.ok` — দুটো আলাদা করে বলে দেয় কোনটা বন্ধ, তাই এলোমেলো অনুমান না করে সরাসরি সমস্যার জায়গায় যেতে পারবেন। বিস্তারিত ফিক্স [user-guide-bn.md এর Troubleshooting অংশে](user-guide-bn.md#৯-troubleshooting)।
